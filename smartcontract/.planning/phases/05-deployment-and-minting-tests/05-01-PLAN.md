Add a `describe("Cap enforcement")` block inside the top-level `describe("RoxasToken")` to test TEST-04.

**Create a nearCapFixture** (named function) that:
1. Deploys the contract (deployer gets 1M RXS initial supply)
2. Gets all signers via `ethers.getSigners()` (Hardhat provides 20 by default)
3. Uses a loop: each round, every signer mints `parseEther("1000")`, then `networkHelpers.time.increase(61)` to reset cooldown
4. Continues until `totalSupply` is within 1000 RXS of the cap (i.e., `cap - totalSupply <= parseEther("1000")`)
5. Returns `{ token, signers }`

The loop math: initial = 1M, cap = 10M, need 9M more. 20 signers x 1000 RXS = 20,000 per round. 9,000,000 / 20,000 = 450 rounds. Each round is fast on Hardhat Network.

**Set a generous Mocha timeout** on the describe block: `this.timeout(120_000)` (2 minutes) since the fixture loop runs ~9000 transactions. The fixture is snapshotted by loadFixture, so it only runs once.

**Important:** Use `function()` syntax (not arrow function) for the describe callback so that `this.timeout()` works.

**Tests in the Cap enforcement block:**
1. `it("should revert when mint would exceed cap")` -- TEST-04:
   - Load nearCapFixture
   - Get current `totalSupply()` and `cap()`
   - Calculate `remaining = cap - totalSupply`
   - If remaining > 0, first advance time by 61s (so signers can mint again), then use signers to fill up until remaining < parseEther("1000")
   - Advance time by 61s again for cooldown
   - Attempt `token.connect(signer).mint(parseEther("1000"))` where remaining < 1000 RXS
   - Assert `.to.be.revertedWithCustomError(token, "ERC20ExceededCap")`

2. `it("should allow minting exactly to the cap")` -- TEST-04 (boundary):
   - Load nearCapFixture
   - Calculate remaining = cap - totalSupply
   - If remaining > 0 and remaining <= parseEther("1000"), advance time 61s and mint exactly `remaining`
   - Assert `totalSupply()` now equals `cap()`
   - Then attempt one more mint of any amount (e.g., parseEther("1")) and assert `revertedWithCustomError(token, "ERC20ExceededCap")`

**Alternative simpler approach if the loop is too complex:** Create the nearCapFixture to fill supply close to cap, then in the test:
- Advance time 61s
- Attempt a mint of parseEther("1000") from a signer whose cooldown has elapsed
- Assert revert with ERC20ExceededCap
This is simpler and still proves the cap enforcement works.

Use the simpler approach if the exact-boundary test proves fragile. The core requirement is that minting reverts when totalSupply would exceed cap.
