## Spacing Scale

Declared values (NativeWind Tailwind equivalents, all multiples of 4):

| Token | Value | NativeWind Class | Usage |
|-------|-------|-----------------|-------|
| xs | 4px | `p-1`, `gap-1` | Icon gaps, inline tight spacing |
| sm | 8px | `p-2`, `gap-2` | Compact row sub-element spacing |
| md | 16px | `px-4`, `gap-4` | Transaction row horizontal padding (matches existing ConnectedScreen `px-8` halved for rows) |
| lg | 24px | `p-6`, `gap-6` | Section-level gaps (ConnectedScreen uses `gap-6`) |
| xl | 32px | `p-8`, `gap-8` | Screen horizontal padding (ConnectedScreen `px-8`) |
| 2xl | 48px | `py-12` | Scroll container vertical breathing room |
| 3xl | 64px | `mt-16` | CTA group top margin (ConnectScreen uses `mt-16`) |

Transaction row padding: `px-4 py-3` (16px horizontal, 12px vertical) — sourced from RESEARCH.md TransactionRow example, consistent with existing card padding pattern.

Section header spacing: `px-4 pt-4 pb-2` — 16px horizontal, 16px top, 8px bottom.

Exceptions:
- Touch target for Disconnect button: minimum 44px height (accessibility) — implemented via `h-11 w-11` per existing ConnectedScreen pattern.
- Skeleton pulse rows: `py-3` vertical (12px) to match live row height and prevent layout shift on data arrival.

## Interaction Contract

| Interaction | Behavior |
|-------------|----------|
| Tap transaction row | No action — display-only for v1 (locked from CONTEXT.md) |
| Pull down on FlatList | Triggers `onRefresh`: sets `refreshing: true`, increments `refreshTrigger`, re-fetches balance AND transactions simultaneously |
| During refresh | Existing transaction rows stay visible; native RefreshControl spinner appears at top; no skeleton replacement |
| Initial load | 3 TransactionSkeleton rows replace transaction list area; header (balance/address) renders normally |
| Empty state reached | "No transactions yet" centered text in place of rows; section header shows "Transactions (0)" |
| Tap Disconnect | Clears session, returns to ConnectScreen — unchanged from Phase 3 |
| Tap Copy address | Copies address to clipboard, shows "Copied!" for 2 seconds — unchanged from Phase 3 |

## Copywriting Contract

| Element | Copy | Source |
|---------|------|--------|
| Section header | `Transactions (N)` where N is count of displayed transactions | CONTEXT.md locked decision |
| Section header (empty) | `Transactions (0)` | CONTEXT.md locked decision |
| Empty state | `No transactions yet` | CONTEXT.md locked decision — "simple and clean" |
| Incoming amount format | `+{value} ETH` (e.g., `+0.5000 ETH`) | CONTEXT.md locked decision |
| Outgoing amount format | `-{value} ETH` (e.g., `-0.0050 ETH`) | CONTEXT.md locked decision |
| Self/zero amount format | `{value} ETH` (no prefix) | CONTEXT.md locked decision |
| Timestamp format | `{N}m ago` / `{N}h ago` / `{N}d ago` / `{N}mo ago` / `just now` | RESEARCH.md Pattern 6 |
| Address truncation format | `0x1234...abcd` (6+4) | CONTEXT.md locked decision |
| Error state (transactions fetch failed) | `Could not load transactions.` — inline below section header (Phase 5 polishes error UX; Phase 4 shows raw error string from hook) | Default — Phase 5 handles retry affordances |
| Disconnect button | `Disconnect` | Existing ConnectedScreen — unchanged |
| Copy button | `Copy` / `Copied!` | Existing ConnectedScreen — unchanged |

Destructive actions in this phase: None introduced. Disconnect is carried from Phase 3 and has no confirmation dialog (tap = immediate disconnect per existing pattern).
